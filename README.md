# ПОС — Преподавательская оценка студентов

Консольная программа на C++17. Можно добавлять студентов и критерии. Можно ставить и исправлять оценки. Итог считается автоматически. Данные сохраняются в `pos_data.txt`. Результаты можно выгрузить в CSV.

## Сборка

```bash
cmake -S . -B build
cmake --build build
```

Запуск из папки проекта:

```bash
./build/pos
```

В Windows вместо последней команды запустить `build/Debug/pos.exe` или `build/pos.exe`. Это зависит от генератора CMake.

Тесты:

```bash
ctest --test-dir build --output-on-failure
```

## Как пользоваться

1. Пункт 1 — добавить студента. Например `Ivan`.
2. Пункт 3 — добавить критерий `Exam`. Максимум `10`. Вес `3`.
3. Пункт 3 — добавить критерий `Homework`. Максимум `20`. Вес `1`.
4. Пункт 5 — поставить студенту `8` за экзамен и `10` за домашку.
5. Пункт 8 — посмотреть итог. Для весового режима будет `72.50%`.
6. Пункт 9 — записать результат в `results.csv`.

ID студента и критерия можно узнать через пункты 2 и 4. Повторная оценка по той же паре заменяет старую. Пункт 7 удаляет оценку. Пункты 10 и 11 удаляют студента или критерий вместе с его оценками.

Если оценки нет то за этот критерий в итоге будет 0. Это принятое для работы правило.

Формула весового итога:

`result = 100 * sum((score / max_score) * weight) / sum(weight)`

Второй режим считает все критерии с одинаковым весом. Если критериев нет то итог равен 0.

## DDD

Общий язык модели: `Student` — студент. `Criterion` — критерий. `Evaluation` — оценка. `FinalScoreService` — расчёт итога.

- **Entity:** `Student` и `Criterion`. У них есть ID. Два студента с одним именем могут быть разными.
- **Value Object:** `Score`. Важен сам балл. При создании проверяется диапазон.
- **Aggregate Root:** `Course`. Хранит студентов и рубрикатор с оценками. Все изменения проходят через его методы.
- **Инварианты:** нельзя поставить балл выше максимума или ниже нуля. Нельзя оценить несуществующего студента или критерий. У одной пары студент-критерий есть только одна текущая оценка.
- **Repository:** `ICourseRepository`. Он задаёт интерфейс загрузки и сохранения.
- **Domain Service:** `FinalScoreService`. Считает результат по оценкам и критериям. Итог отдельно не хранится.

## Архитектура

Используется облегчённая **Ports and Adapters**.

```text
domain/domain.hpp + domain/domain.cpp                 сущности и правила
application/application.hpp + application/application.cpp сценарии и порты
infrastructure/infrastructure.hpp + infrastructure/infrastructure.cpp файлы и CSV
infrastructure/console.hpp + infrastructure/console.cpp консольное меню
main.cpp                                              запуск приложения
```

Зависимости направлены внутрь:

`main -> infrastructure -> application -> domain`

`infrastructure` реализует интерфейсы из `application`. `domain` не знает про файлы и консоль. Объекты собираются в `AppContainer` в инфраструктурном слое. Это простой DI-контейнер через конструкторы.

## Паттерны GoF

- **Factory — `EvaluationFactory`.** Создаёт оценку. Проверяет студента и критерий. Также проверяет диапазон через `Score`. Это не даёт создать неверную оценку.
- **Facade — `PosFacade`.** Даёт консоли простые операции. В `main.cpp` не нужно напрямую работать с хранилищем и расчётом.
- **Strategy — `IScoreStrategy`.** Есть `WeightedStrategy` и `EqualStrategy`. Можно менять правило весов без изменений расчёта.

## Хранение

`FileCourseRepository` сохраняет студентов и критерии с ID. Оценки сохраняются отдельно в том же текстовом файле. При запуске файл загружается. Формат предназначен только для этой программы. Редактировать его вручную не нужно.

`CsvExporter` пишет отдельный файл с итогами. Для CSV используется кодировка UTF-8 если терминал и имена работают в UTF-8.
